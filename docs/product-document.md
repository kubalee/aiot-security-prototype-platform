# 安防 AIoT 联动中枢讲解文档

## 1. 先用一句话说明

这套系统的作用是：当摄像头、门禁、传感器等安防设备发现异常后，系统会把现场画面、AI 判断、需要联动的设备、需要通知的人集中到一个看板里，让值班人员更快知道发生了什么、应该怎么处理、处理进度到哪一步。

简单说，它不是单纯看监控，而是把“发现问题、判断问题、通知人员、联动设备、跟踪结果”串在一起。

## 2. 为什么要做这套系统

很多安防场景里，问题不是没有设备，而是设备之间没有真正配合起来。

以前可能会遇到这些情况：

- 摄像头发现异常了，但值班人员还要自己去找画面。
- AI 设备报了警，但真假还要人工一点点判断。
- 要通知保安、物业、运维时，需要手动打电话或发消息。
- 门禁、广播、工单、巡检这些系统各自独立，处理速度慢。
- 事情处理完以后，谁看过、谁处理过、有没有闭环，不容易回看。

这套系统想解决的就是：让设备报警之后，后面的处理动作能自动跟上，人只需要确认和指挥。

## 3. 适合用在哪些地方

这套原型适合讲给这些场景：

| 场景 | 可以解决的问题 |
| --- | --- |
| 园区 | 人员闯入、重点区域异常、夜间巡防 |
| 写字楼 | 门禁异常、陌生人员停留、消防通道占用 |
| 仓库 | 货区异常、烟火风险、人员靠近危险区域 |
| 学校 | 校门口聚集、重点区域巡查、夜间异常 |
| 物业 | 小区周界、车库、设备间、出入口管理 |

它的核心价值不是替代人，而是让人更快看到重点、更快做决定。

## 4. 谁会使用

| 使用者 | 他关心什么 |
| --- | --- |
| 值班主管 | 现在有没有紧急情况，应该先处理哪一个 |
| 安保人员 | 我需要去哪里，现场是什么情况 |
| 物业负责人 | 事情有没有通知到人，有没有处理完成 |
| 运维人员 | 摄像头和设备是否正常，视频能不能看 |
| 管理人员 | 一段时间内发生了多少事件，处理效率怎么样 |

讲解时可以这样说：不同人员看到的是同一件事的不同角度，值班人员看处置，管理人员看结果，运维人员看设备。

## 5. 一件事情是怎么被处理的

可以用一个例子来讲：

假设晚上仓库门口有人长时间停留。

1. 摄像头先发现异常，把事件传到系统里。
2. 系统在指挥看板上弹出这条事件，并显示对应的视频画面。
3. 系统里的 AI 会判断这件事严不严重，比如是否像误报、是否需要立刻处理。
4. 系统给出建议动作，比如通知值班主管、打开附近广播、创建巡检任务。
5. 值班人员可以在看板上点击执行这些动作。
6. 系统把通知发给相关人员，也可以把指令发给门禁、广播、工单等系统。
7. 处理完成后，值班人员确认闭环。
8. 后续管理人员可以在统计页看到这类事件发生了多少、处理是否及时。

这条流程要表达的重点是：设备负责发现，AI 帮忙判断，系统负责联动，人负责最终确认。

## 6. PC 指挥看板怎么讲

PC 看板是值班室大屏或电脑端使用的主界面。

讲解时可以按照从左到右、从上到下的顺序：

| 区域 | 讲解方式 |
| --- | --- |
| 顶部统计 | 先看今天有多少事件、多少正在处理、视频是否在线 |
| 事件列表 | 当前发生的事情都在这里，紧急的排在前面 |
| 视频画面 | 点击事件后，直接看到对应摄像头画面 |
| AI 判断 | 系统告诉值班人员这件事大概是什么情况 |
| 处置步骤 | 可以看到事件从发现到处理完成走到哪一步 |
| 联动设备 | 这里展示哪些设备或系统需要一起动作 |
| 人员通知 | 可以看到通知发给了谁，谁已经收到 |
| 操作记录 | 每次点击和处理动作都会留下记录，方便之后回看 |

这个页面的讲解重点是：值班人员不需要在多个系统之间来回切换。

## 7. 手机看板怎么讲

手机看板适合给外勤人员、安保人员或管理人员使用。

它的重点不是展示所有信息，而是让人在手机上快速知道三件事：

- 发生了什么。
- 在哪里发生。
- 需要我做什么。

比如巡逻人员收到通知后，可以打开手机看板，看到事件位置、风险等级、现场画面和处理要求。

## 8. 统计分析界面怎么讲

统计分析界面是给管理人员看的。

它回答的是这些问题：

- 今天一共发生了多少事件。
- 哪类事件最多。
- 哪些区域更容易出问题。
- 平均处理时间怎么样。
- 哪些事件还没处理完。
- 视频、设备、通知是否都正常。

讲解时可以这样说：指挥页负责处理当下，统计页负责复盘和管理。

## 9. 配置界面怎么讲

配置界面主要给管理员或运维人员使用。

它可以维护这些内容：

- 接入哪些摄像头。
- 哪些视频流启用或停用。
- 事件需要通知哪些人。
- 哪些设备或系统可以被联动。
- 后续对接真实后台时，需要哪些接口。

这里不用讲太深，只需要让听众知道：系统不是写死的，后续可以按现场设备和业务流程调整。

## 10. 关于视频流怎么说明

如果有人问“为什么有摄像头地址还不能直接在网页播放”，可以这样解释：

摄像头给出的原始视频地址，浏览器通常不能直接打开。我们需要一个本地服务把它转换成网页可以播放的地址，再由前端页面展示出来。

也就是说：

- 摄像头负责提供原始画面。
- 本地服务负责把画面转换成网页能看的格式。
- 看板负责把视频和事件放在一起展示。

摄像头账号、密码这类敏感信息不会放到公开代码里。

## 11. 演示时建议怎么走

可以按这个顺序演示：

1. 先打开 PC 指挥看板，说明这是值班人员的主界面。
2. 点击一个事件，展示事件列表、视频画面和 AI 判断会一起变化。
3. 点击建议动作，说明系统可以帮助值班人员快速处置。
4. 点击物联系统联动，说明门禁、广播、工单、巡检可以被统一调度。
5. 点击人员通知，说明相关人员可以被同步通知。
6. 点击确认闭环，说明事件可以从发现走到处理完成。
7. 再进入统计分析界面，说明管理人员可以看到整体情况。
8. 最后进入配置界面，说明摄像头、接口、联动规则后续都可以接真实系统。

这条演示路线适合对外讲解，也适合内部评审。

## 12. 这套系统最终带来的价值

| 价值 | 说明 |
| --- | --- |
| 更快发现 | 设备发现异常后，第一时间进入看板 |
| 更快判断 | AI 帮助值班人员判断事件轻重缓急 |
| 更快通知 | 系统可以把消息发给相关人员 |
| 更快联动 | 门禁、广播、工单、巡检等动作可以统一触发 |
| 更好追踪 | 每一步处理都有状态，方便回看 |
| 更好管理 | 管理人员可以通过统计页看到整体安全情况 |

## 13. 可以用来结束讲解的一句话

这套系统的目标，是让安防从“人盯着多个设备看”，变成“设备发现问题，系统组织处理，人做关键确认”。
